> 版本：v0.1 · 2026-11-05

## 1. 测试策略

| 层 | 手段 | 说明 |
| --- | --- | --- |
| S3 业务逻辑 | Rust 集成测试 `cargo test --test integration` | 与 Tauri command 复用同一 `ops` 模块，直接打真实集群 |
| 命令层（IPC） | Tauri command 薄封装 | 由 ops 保证；UI 手工验证 |
| UI | `pnpm dev` 浏览器 mock 模式 + `pnpm tauri dev` 真实模式 | mock 与真实共享同一 UI 代码 |
| 环境变量 | `SSSC_ENDPOINT / SSSC_REGION / SSSC_AK / SSSC_SK / SSSC_IT_WORK_BUCKET` | 一套代码适配任意 S3 兼容集群 |

运行方式：

```bash
cd src-tauri && cargo test --test integration -- --nocapture --test-threads=1
# 指向其他集群：
SSSC_ENDPOINT=http://minio:9000 SSSC_AK=xxx SSSC_SK=yyy cargo test --test integration
```

## 4. 发现的目标集群服务端怪癖（非客户端 bug）

针对 SeaweedFS 30GB 4.50（10.120.18.231:8333），diag.rs 中有完整复现：

1. **新桶不可写**：经 S3 CreateBucket 创建的桶，任何上传（任意大小/方式）稳定返回 500 `InternalError`；预建桶（hdd-demo 等）一切正常。非一致性延迟（5s 后仍失败）。
2. **读后删失败**：对象被 GET（预签名或 SDK 下载）读取后，DeleteObject 稳定 500；未读对象（或覆盖重写后）可正常删除。
3. 端口混淆：8888 是 Filer Web UI，S3 网关在 8333。

测试侧规避（integration.rs 内置）：工作桶探测 + 自动回退已有桶；删除前覆盖重写；残留自动清理。
产品侧含义：**印证 docs/02 的「能力探测 + 差异化降级」设计**——SSSC 的错误呈现（Code/Message/RequestId）在这些场景下均完整工作。遗留：`hdd-demo/diag-flat.bin`（16B）因怪癖 2 无法删除，建议集群侧重启 filer 后手工清理；桶内 `s3browser-13-6-5.exe`、`uss-t.txt` 为用户数据，未触碰。
