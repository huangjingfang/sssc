# S3C — 跨平台 S3 多集群桌面客户端 · 产品概述

> 项目代号：**SSSC**（S3 Super Client，下文称「本产品」）
> 文档版本：v0.1 · 2026-11-05

---

## 1. 产品定位

一款**跨平台（Windows / macOS / Linux）桌面端 S3 对象存储客户端**，面向**研发人员**，支持同时接入与切换多个 S3 集群（AWS S3 与 S3 兼容的私有部署，如 MinIO、Ceph RGW、SeaweedFS，以及阿里云 OSS、腾讯云 COS 等 S3 兼容端点）。

一句话定位：**「研发人员本地的多集群对象存储工作台」**——不只是上传下载工具，而是日常开发工作流中桶管理、对象操作、预签名分享、策略调试的控制台。

### 1.1 目标用户画像

| 画像 | 场景 |
| --- | --- |
| 后端/平台研发 | 日常向 MinIO/测试集群上传发布产物、拉取日志归档、调试桶策略与 CORS |
| 数据/算法研发 | 大数据集上传下载（分块、断点续传）、按前缀浏览结果文件 |
| DevOps / SRE | 多套环境（dev/staging/prod）集群对照管理、批量迁移、生命周期规则配置 |
| 独立开发者 | 用 S3 兼容存储做静态资源与备份，需要生成预签名链接分享 |

### 1.2 设计原则（产品层）

1. **研发优先**：暴露完整技术细节（ETag、StorageClass、VersionId、Request ID、错误码），不做「傻瓜化裁剪」。
2. **多集群一等公民**：任何界面与操作都以「当前集群上下文」为基础，切换零成本、零歧义。
3. **键盘友好**：命令面板（⌘K）、快捷键、路径导航，符合终端用户习惯。
4. **安全本地化**：凭据仅存于本机系统凭据库（Keychain / Credential Manager / libsecret），不上传任何远端。

## 2. 多集群管理需求

### 2.1 核心概念模型

```
Profile（集群档案）
├── name            显示名，如 "prod-minio"
├── endpoint        https://s3.example.com:9000（自定义端点，path-style 优先）
├── region          区域，兼容端点可填 us-east-1
├── accessKey / secretKey   AK/SK（存系统凭据库，明文不落盘）
├── style           path-style | virtual-hosted-style
├── tls             证书校验开关 / 自签 CA（研发自签场景）
└── color / tag     视觉标识（侧栏徽标），如 prod=红、dev=绿
```

- 一个 Profile = 一个集群上下文；UI 顶部/侧栏常驻当前集群指示器。
- 支持从 `~/.aws/credentials` 与环境变量导入 Profile。
- 连接测试（ListBuckets 探活）+ 延迟显示。

### 2.2 多集群功能需求

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| MC-1 | Profile 增删改查、连接测试、启用/禁用 | P0 |
| MC-2 | 集群快速切换器（侧栏 + ⌘K 命令面板 + Ctrl+数字快捷切换） | P0 |
| MC-3 | 当前集群全局视觉标识（色条/徽标），防止误操作 prod | P0 |
| MC-4 | 跨集群复制/移动对象（同端直拷 server-side copy 或经本地中转） | P1 |
| MC-5 | 同屏对比：双集群桶列表对照视图（迁移前核对） | P2 |
| MC-6 | 危险操作二次确认中显示目标集群名 | P0 |
| MC-7 | Profile 导入导出（凭据脱敏） | P2 |

### 2.3 与框架选型的关联（详见《01-技术选型》）

多集群意味着：并发多路 HTTP 连接池、SIGV4 签名（自定义 endpoint、path-style、自签证书）、大量传输任务的后台调度（断点续传、限速）、系统凭据库访问、系统托盘常驻与传输进度通知。这些能力决定了后端语言生态（S3 SDK 成熟度）与桌面集成能力是选型的核心权重。
