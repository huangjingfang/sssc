# S3 能力清单与功能需求（调研 → 产品需求）

> 文档版本：v0.1 · 2026-11-05
> 依据 AWS 官方文档与 MinIO / Ceph RGW / 阿里云 OSS / 腾讯云 COS 兼容性文档调研整理，来源见文末。

## 1. S3 API 能力全景（客户端视角摘要）

### 1.1 Service / Bucket / Object 三级 API

| 层级 | API | 客户端要点 |
| --- | --- | --- |
| Service | ListBuckets（分页 ContinuationToken/MaxBuckets）、CreateBucket（LocationConstraint）、DeleteBucket（仅空桶，非空返回 `BucketNotEmpty`）、GetBucketLocation、HeadBucket | 桶数 >10000 需分页；桶名全局唯一；us-east-1 特例：重建自己的桶返回 200 |
| Bucket | Versioning / Lifecycle / Policy / CORS / Tagging / Encryption / Replication / Notification / Website / Logging / PublicAccessBlock 等 Get/Put/Delete 组 | 兼容实现支持度差异最大，**必须能力探测 + 优雅降级** |
| Object | Put/Get/Delete/Head/CopyObject、DeleteObjects（≤1000 key/次）、GetObjectAttributes、ListObjectsV2、MPU 全套 | CopyObject >5GB 必须用 UploadPartCopy；批量删除注意分批 |

### 1.2 ListObjectsV2 关键参数（对象浏览器的基础）

- `prefix` + `delimiter=/` → `CommonPrefixes` 聚合"目录"，是目录树浏览的实现方式；
- `max-keys` 默认/上限 1000，`continuation-token` 不透明游标分页；
- `start-after` 字典序跳入（快速定位）；
- `fetch-owner`（V2 默认不返回 Owner）；
- **`encoding-type=url` 硬坑**：key 含中文/特殊字符不指定会导致解析出错——研发用户 key 命名五花八门，必须默认开启。

### 1.3 分块上传（MPU）与断点续传

- 三段式：CreateMultipartUpload → UploadPart（并发、乱序）→ Complete；Abort 清理；ListParts/ListMultipartUploads 恢复与巡检。
- 约束：part 5MB~5GB、≤10000 parts、单对象 ≤5TB。
- **S3 协议无原生续传**：上传续传 = 本地持久化 uploadId + 已完成分块 ETag（ListParts 校对）补传缺失分块；下载续传 = `Range: bytes=x-y`（越界返回 416 `InvalidRange`）。
- 未完成 MPU 持续计费 → 客户端应提供残留 MPU 巡检/清理，并提示配置 `AbortIncompleteMultipartUpload` 生命周期规则。

### 1.4 高级特性速览

- **Versioning**：三态；删除产生 DeleteMarker；ListObjectVersions / 按 versionId 取历史。
- **Lifecycle**：过滤器 + Transition / Expiration / NoncurrentVersion* / AbortIncompleteMultipartUpload；单桶 ≤1000 规则。
- **存储类**：STANDARD / IA / ONEZONE_IA / INTELLIGENT_TIERING / GLACIER_IR / GLACIER / DEEP_ARCHIVE 等；归档类直接 Get 返回 403 `InvalidObjectState`，必须先 RestoreObject。
- **加密**：SSE-S3 / SSE-KMS / SSE-C（HTTPS 强制、丢密钥即丢数据）。
- **CORS / Policy / Tagging**：浏览器直传、权限调试、成本分账的抓手。
- **Presigned URL**：GET/PUT/HEAD；CLI/SDK(SigV4) 最长 7 天；STS 临时凭证签名时 URL 随凭证过期提前失效。

### 1.5 SigV4 与自定义 endpoint（私有部署核心）

- 授权头四段式；canonical request + HMAC-SHA256 派生；**签名 region 必须与 endpoint 匹配——自定义 endpoint 场景最常见的签名失败原因**。
- path-style vs virtual-hosted：私有部署（MinIO/Ceph/SeaweedFS）多数只有 `host:port`，需 **endpoint + region + path/virtual 开关 + http(s)/自签证书** 完整可配；注意腾讯云 COS 2024 后新建桶仅支持 virtual-hosted、桶名固定带 APPID 后缀。
- STS 临时凭证签名必须带 `x-amz-security-token`。

### 1.6 错误模型（研发体验的关键）

- 每个错误呈现三元组：**Code（程序分类）+ Message（人读）+ RequestId（报障凭证）**，另有 `x-amz-id-2`。
- 常见错误码：NoSuchBucket/NoSuchKey 404、BucketAlreadyExists/BucketNotEmpty 409、AccessDenied/InvalidAccessKeyId/SignatureDoesNotMatch/RequestTimeTooSkewed（时钟漂移）403、SlowDown 503、InvalidPart 400、InvalidRange 416、InvalidObjectState 403、PermanentRedirect/TemporaryRedirect（**响应体内带正确 endpoint，客户端应提示自动修正**）。
- 重试：5xx/SlowDown/429 指数退避 + 抖动（默认 3 次）；重试须重算签名；批量任务全局并发控制，遇 SlowDown 自动降并发。

## 2. 兼容生态差异矩阵

| 能力 | AWS | MinIO | Ceph RGW | 阿里 OSS(S3) | 腾讯 COS(S3) | SeaweedFS |
| --- | --- | --- | --- | --- | --- | --- |
| 对象核心 API + MPU | ✅ | ✅ | ✅ | ✅ | ✅ | ✅（子集） |
| ListObjectsV2 高级参数 | ✅ | ✅ | ✅ | ⚠️ 部分 | ⚠️ 部分 | ⚠️ 部分 |
| path-style | ⚠️ 收紧中 | ✅ | ✅ | ⚠️ | ❌（2024 后新桶） | ✅ |
| ACL | ✅ | ❌ | ⚠️ canned 集不同 | ⚠️ | ⚠️ | ❌ |
| CORS 配置 | ✅ | ❌（全放开） | ✅ | ✅ | ✅ | ❌ |
| Website | ✅ | ❌ | ✅ | ✅ | ✅ | ❌ |
| Lifecycle | ✅ | ⚠️ 自研 ILM | ✅ | ✅ | ✅ | ❌ |
| 版本控制 / Object Lock | ✅ | ✅ | ✅ | ⚠️ | ⚠️ | ❌ |
| 新 checksum 族（CRC32C/CRC64） | ✅ | ⚠️ 有出入 | ⚠️ | ⚠️ | ⚠️ | ⚠️ |
| 错误体规范（RequestId 等） | ✅ | ⚠️ | ⚠️（缺 x-amz-id-2） | ⚠️ | ⚠️ | ⚠️ |

**设计结论**：客户端不假设全兼容，采用「预设差异掩码（按 Profile 类型）+ 运行时能力探测（GetBucketXxx 探测）」双轨，不支持的配置入口直接隐藏/置灰并说明原因。

## 3. 功能需求优先级（面向研发用户）

### P0 — MVP

| 模块 | 需求 |
| --- | --- |
| 连接管理 | 多集群 Profile（endpoint/region/AK-SK/STS/path-virtual/http(s)/自签 CA），连接测试，`~/.aws/credentials` 导入 |
| 桶管理 | 列表（分页）、创建（区域选择）、删除（空桶校验 + 二次确认） |
| 对象浏览 | ListObjectsV2 目录树（delimiter）、分页、`encoding-type=url` 默认开启、start-after 快速定位、面包屑 + 前缀跳转 |
| 对象操作 | 上传（MPU 并发 + 断点续传）、下载（Range 分段并发 + 续传）、删除（单个/批量 ≤1000/批）、复制/改名（服务端 Copy）、元数据详情（HeadObject：ETag/StorageClass/VersionId/Checksum） |
| 传输引擎 | 任务队列、暂停/恢复/重试（指数退避）、限速、全局并发、SlowDown 自动降并发 |
| 预签名 | GET/PUT、可调有效期（提示 7 天上限与 STS 失效） |
| 错误与可观测 | Code/Message/RequestId 三元组完整展示、请求日志面板、Redirect 错误提示修正 endpoint |

### P1 — 竞争力

- 桶配置：Versioning（版本浏览/恢复/删 DeleteMarker）、Lifecycle 规则编辑器、Tagging、CORS、加密（SSE 三模式）、Policy 编辑器（JSON 高亮 + 本地校验）
- MPU 残留巡检与清理
- 存储类选择与展示、归档对象 RestoreObject 及恢复状态跟踪
- 跨集群批量迁移/同步（服务端复制优先，迁移报告）
- 能力探测框架 + 按集群类型差异化 UI

### P2 — 增值

- Website / Replication / Inventory 配置（仅支持的集群）
- 签名调试器（SigV4 排障：时钟、region、header diff）、权限诊断工作台
- 操作导出为 `aws s3` / `mc` CLI 命令、脚本化批处理

## 4. 对架构的直接约束

1. 后端必须自建**传输状态库**（任务、分块指纹、uploadId 持久化）——这决定选型时后端语言的并发与文件 IO 能力权重。
2. SigV4 签名、自定义 endpoint、自签证书、STS —— 需要**成熟且可深度定制请求层的 S3 SDK**（或在 SDK 之上包一层 transport）。
3. 能力探测 + 差异掩码 —— 需要前端能按运行时能力动态渲染配置界面（前端框架自由度）。
